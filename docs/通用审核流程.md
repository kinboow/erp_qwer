# 通用审核流程（downstream_order_reviews）

> 核心文件: `downstream_orders.py`
> 
> 本文档描述从消息接收 → AI 解析 → 人工审核 → ERP 下单的完整流程。

---

## 一、流程总览

```
企微消息回调
  │
  ▼
create_review_from_callback
  ├─ 提取消息字段（发送者、群ID、内容、附件）
  ├─ 跳过非群消息 / 不支持的消息类型 / 空内容
  ├─ 写入 downstream_order_reviews 表
  └─ 自动调用 parse_review_content → AI 解析
       │
       ▼
  前端审核列表（SSE 实时推送）
  ├─ 审核员查看 AI 解析结果
  ├─ 可手动修改订单内容
  └─ 选择操作：
       ├─ ✅ 审核通过 → approve_review → ERP 创建订单+审核
       ├─ 🔄 替换旧单 → replace_old_order → 取消未发货+创建新单
       ├─ ✏️ 手动录单 → manual_order → 用手动数据创建订单
       ├─ ❌ 废单 → void_review → 标记作废
       └─ ↩️ 恢复待审 → revert_to_pending
```

---

## 二、消息接收与审核记录创建

> 入口: `create_review_from_callback(db, payload, instance_id)`
>
> **注意**: 此函数原本是未分类群的通用兜底，现已从 `ingest_runtime_message` 中移除。
> 仅客户群通过 `at_order_handler` 中的 `_process_order` → `_write_review` 写入审核记录。

### 2.1 消息提取（`_extract_callback_message`）

从 payload 中兼容 3 种回调格式提取字段：

| 字段 | 说明 |
|------|------|
| `sender_id` | 发送者 wxid |
| `sender_name` | 发送者昵称 |
| `room_id` | 群 ID |
| `room_name` | 群名称 |
| `message_type` | `text` / `image` / `file`（自动推断） |
| `content_text` | 文字内容 |
| `attachment_name` | 附件文件名 |
| `attachment_url` | 附件 URL / CDN 地址 |
| `attachment_base64` | 附件 base64（如果回调直接携带） |
| `attachment_mime` | MIME 类型 |

### 2.2 跳过条件

以下消息不创建审核记录：

| 条件 | skip_reason |
|------|-------------|
| payload 为空 | `empty_payload` |
| 非群消息（私聊） | `not_group_message` |
| 消息类型不在 `{text, image, file}` 中 | `unsupported_message_type` |
| 无可用内容 | `empty_message_content` |

### 2.3 写入 `downstream_order_reviews` 表

```sql
INSERT INTO downstream_order_reviews (
  review_uid,         -- 唯一标识 RV + 日期 + 随机hex，如 RV250501A3F1
  source_type,        -- wechat_ngcbot_v3 / wechat_ngcdemo_legacy / wechat_at_order
  instance_id,        -- 企微实例 DB ID
  room_id, room_name, -- 群信息
  sender_id, sender_name, -- 发送者信息
  message_type,       -- text / image / file
  content_text,       -- 文字内容
  attachment_name, attachment_url, attachment_mime, attachment_base64,
  callback_payload,   -- 原始 payload JSON
  parse_status,       -- pending / pending_attachment / success / failed
  review_status,      -- pending / approved / replaced / manual_ordered / voided / exception
  customer_id, customer_name
)
```

- 如果附件缺少 base64 → `parse_status = 'pending_attachment'`
- 否则 → `parse_status = 'pending'`

### 2.4 自动触发 AI 解析

写入后立即调用 `parse_review_content(db, review_id)`

## 三、AI 解析流程（`parse_review_content`）

> 入口: `parse_review_content(db, review_id)`
>
> 与客户群 `_process_order` 共享相同的 3 步 AI 流程

### 3.0 附件准备

- 如果是 `image`/`file` 且缺少 `attachment_base64`：
  - 调用 `_download_review_attachment_content` 从企微 CDN 下载
  - 支持 `wx_download`（CDN url+auth_key+aes_key）和 `c2c_download`（file_id+aes_key）两种模式
  - 下载后存入 `attachment_base64` 字段
- Excel 文件额外调用 `_extract_excel_summary` 提取文本摘要

### 3.1 — 🤖 智能体 A：款号提取 Agent

> 函数: `ai_order_parser.extract_product_nos(context_messages, catalog=catalog)`

**前置**: `query_current_year_catalog(db)` 加载本年产品目录

**请求参数**:
```json
{
  "model": "<vision_model 或 model>",
  "temperature": 0.1,
  "max_tokens": 16384,
  "messages": [
    {"role": "system", "content": "<_PRODUCT_NO_EXTRACT_PROMPT_TEMPLATE>"},
    {"role": "user", "content": "<多模态内容>"}
  ]
}
```

**AI 返回**: `{"raw_texts": [...], "rotation_angle": 0}`

**代码层硬校验**:
- `_match_catalog(raw_texts, catalog)` 精确匹配本年产品目录
- 匹配规则: `product_no 精确` > `alias 精确` > `product_name 精确` > `子串匹配`

**分支**:
- 无匹配款号 → `parse_status = 'failed'`，记录 `ai_error` → **中止**
- 有匹配 → 继续

### 3.1.5 — 图片旋转

- 如果 `rotation_angle != 0` → `rotate_images_in_messages` 用 PIL 旋转

### 3.2 — 库存查询（非 AI）

> 函数: `query_product_context_structured(db, product_nos)`

- 查询 `erp_products` 获取每个款号的可选颜色/尺码
- 查询 `product_name_mappings` 获取别名映射

### 3.3 — 🤖 智能体 B：订单解析 Agent

根据是否有产品上下文走不同分支：

#### 有上下文 → `parse_with_product_context`

```json
{
  "model": "<vision_model 或 model>",
  "messages": [
    {"role": "system", "content": "<动态 _CONTEXT_PARSER_PROMPT_TEMPLATE>"},
    {"role": "user", "content": "<多模态内容>"}
  ]
}
```

- System Prompt 动态注入每个款号的可选颜色列表、可选尺码列表、款号映射关系

#### 无上下文 → `parse_batch`

```json
{
  "model": "<vision_model 或 model>",
  "messages": [
    {"role": "system", "content": "<ORDER_PARSER_SYSTEM_PROMPT + _ORDER_PARSER_CATALOG_SUFFIX>"},
    {"role": "user", "content": "<多模态内容>"}
  ]
}
```

- 后缀注入完整本年产品目录约束

### 3.4 — 代码层硬校验

- `_normalize_order(parsed)` 标准化格式
- 用 `catalog` 的 `valid_pnos` 过滤非本年产品款号
- 过滤后为空 → `parse_status = 'failed'` → **中止**

### 3.5 — 解析成功

```sql
UPDATE downstream_order_reviews
SET parse_status = 'success',
    parsed_order_json = '<结构化订单JSON>',
    ai_error = ''
WHERE id = :review_id
```

`parsed_order_json` 格式:
```json
{
  "customer_name": "客户A",
  "order_date": "2025-05-04 20:00:00",
  "remark": "",
  "items": [
    {
      "product_no": "82761",
      "color": "黑色",
      "sizes": [{"size": "S", "qty": 10}, {"size": "M", "qty": 5}],
      "remark": ""
    }
  ],
  "uncertainties": []
}
```

## 四、前端审核

### 4.1 审核列表

> API: `GET /api/downstream-orders/reviews`
> 
> 只展示 `parse_status = 'success'` 的记录

- 支持按 `review_status` 筛选（`pending` / `approved` / `voided` 等）
- 支持按 `customer_id` 筛选
- SSE 推送: `GET /api/downstream-orders/reviews/stream` — 当有新审核单时实时通知前端

### 4.2 审核详情

> API: `GET /api/downstream-orders/reviews/{id}`

返回完整审核记录，包含：
- 原始消息内容、附件
- AI 解析的 `parsed_order`
- 人工修改的 `manual_order`（如有）
- 关联客户信息
- 审核状态和历史

### 4.3 上下文消息

> API: `GET /api/downstream-orders/reviews/{id}/context-messages`

返回触发消息前后 20 条群聊记录，用于审核员了解上下文

## 五、审核操作

### 5.1 ✅ 审核通过（`approve_review`）

> API: `POST /api/downstream-orders/reviews/{id}/approve`

```
审核通过流程:
  │
  ├─ 1. 重复下单检查
  │     查询该客户最近 35 张 ERP 销售订单的备注
  │     如果备注中已包含 [review_uid] → 拦截，标记 exception
  │
  ├─ 2. 获取订单数据
  │     优先用 manual_order_json（人工修改版），否则用 parsed_order_json（AI 解析版）
  │
  ├─ 3. 注入审核标识
  │     将 [RV250501A3F1] 注入到订单备注开头
  │
  ├─ 4. 调用 ERP 创建销售订单
  │     erp_bridge.create_sales_order(order_data, customer)
  │     → ERP API: 创建订单 + 自动审核
  │
  ├─ 5. 更新审核状态
  │     review_status = 'approved'
  │     erp_order_no = '<ERP单号>'
  │
  ├─ 6. 同步 ERP 数据
  │     ├─ sync_single_order — 同步订单明细到本地 DB（等待完成）
  │     └─ sync_inventory_by_product_nos — 后台异步同步涉及款号的库存
  │
  └─ 7. 自动打印配货单
        auto_print_picking_list(db, order_no)
```

### 5.2 🔄 替换旧单（`replace_old_order`）

> API: `POST /api/downstream-orders/reviews/{id}/replace`

```
替换旧单流程:
  │
  ├─ 1. 重复下单检查（同上）
  │
  ├─ 2. 查询该客户所有未发货订单
  │     erp_bridge.query_unshipped(customer_erp_id, 近5年)
  │
  ├─ 3. 取消所有未发货行
  │     erp_bridge.cancel_unshipped(ids)
  │
  ├─ 4. 创建新订单 + 审核（同上）
  │
  ├─ 5. 更新审核状态
  │     review_status = 'replaced'
  │     replaced_order_no = '被替换的旧单号列表'
  │
  ├─ 6. 同步 ERP 数据
  │
  └─ 7. 自动打印配货单
```

### 5.3 ✏️ 手动录单（`manual_order`）

> API: `POST /api/downstream-orders/reviews/{id}/manual-order`

- 前端提交修改后的 `order_data`
- 流程与审核通过一致，但使用前端提交的数据而非 AI 解析结果
- `review_status = 'manual_ordered'`
- `manual_order_json` 保存手动数据

### 5.4 ❌ 废单（`void_review`）

> API: `POST /api/downstream-orders/reviews/{id}/void`

- 标记 `review_status = 'voided'`
- 下单前检查：如果该 review_uid 已存在于 ERP 订单中 → 拦截为 exception

### 5.5 ↩️ 恢复待审（`revert_to_pending`）

> API: `POST /api/downstream-orders/reviews/{id}/revert-pending`

- 仅 `voided` 或 `exception` 状态可恢复
- 标记 `review_status = 'pending'`

## 六、重试与重新解析

### 6.1 重新 AI 解析

> API: `POST /api/downstream-orders/reviews/{id}/reparse`

- 重新调用 `parse_review_content` 执行完整 3 步 AI 流程
- 适用于 AI 第一次解析失败或需要更新结果的场景

### 6.2 附件重新下载+解析

> API: `POST /api/downstream-orders/reviews/{id}/retry-download`

- 重新从企微 CDN 下载附件
- 下载完成后自动触发 `parse_review_content` 重新解析
- 支持 `force_download` 参数强制重新下载

## 七、ERP 桥接层（`ERPBridge`）

### 7.1 创建销售订单

> 函数: `erp_bridge.create_sales_order(order_data, customer)`

```
1. ERP 登录（确保 session 有效）
2. 将订单数据转换为 CreateSalesOrderRequest:
   - customer_id → ERP 客户编号
   - detail: 按 款号+颜色+尺码数量 拆分明细行
   - 默认值: brand, shipping_method, salesperson, currency 等从 settings 取
3. 调用 ERP API create_order
4. 自动审核: audit_order(order_no, AuditAction.audit)
5. 返回 {order_no, message}
```

### 7.2 查询未发货报表

> 函数: `erp_bridge.query_unshipped(customer_erp_id, dates, datee)`

- 调用 ERP 未发货报表 API，按客户筛选
- 可选按款号过滤

### 7.3 取消未发货

> 函数: `erp_bridge.cancel_unshipped(ids)`

- 批量取消未发货订单行（`sfwg=1`）

## 十、安全机制

### 10.1 重复下单拦截

- 每条审核记录有唯一 `review_uid`（如 `RV250501A3F1`）
- 下单时将 `[review_uid]` 注入 ERP 订单备注
- 下单前查询该客户最近 35 张 ERP 订单，如果备注中已包含该 `review_uid` → 拦截
- 拦截后标记 `review_status = 'exception'`

### 10.2 整单查重

- 下单前可调用 `check_duplicate_order` 检查该客户最近 10 张订单
- 比对逻辑：所有行的 `款号+颜色+尺码+数量` 完全一致 → 判定为重复
- 仅告警，不强制拦截

### 10.3 增量同步

- 下单成功后：
  - **同步订单明细**（`sync_single_order`）— 等待完成
  - **同步库存**（`sync_inventory_by_product_nos`）— 后台异步
- 确保本地数据与 ERP 保持一致

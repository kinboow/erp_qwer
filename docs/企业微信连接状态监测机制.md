# 企业微信连接状态监测机制

## 一、整体架构

系统通过两个独立机制监测企业微信的连接状态，并具备自动恢复能力：

```
┌──────────────────────────────────────────────────────────────┐
│                       后端 (FastAPI)                          │
│                                                              │
│  ┌──────────────────────┐     ┌──────────────────────┐      │
│  │  wechat_health.py     │     │ wechat_ws_service.py │      │
│  │  (健康轮询 每3秒)      │     │  (WebSocket 长连接)   │      │
│  └────────┬─────────────┘     └──────────┬───────────┘      │
│           │                               │                  │
│   POST /api/wechat/overview          维护 WS 连接            │
│   仅以 login_status 判断              readyState 状态机       │
│           │                               │                  │
│     离线 → 自动重启(×2)              断开 → 5秒重连           │
│           → 语音告警(×3)                                      │
│           → 系统消息+动态                                     │
│           → 前端弹窗(ws_notify)                               │
│           → 自动选上恢复的实例                                 │
│                                                              │
└──────────────────────────┬───────────────────────────────────┘
                           │
                    NGCBot V3-QW API
                  (第三方企微 Hook 服务)
```

## 二、健康检查轮询 (`wechat_health.py`)

### 2.1 启动流程

`main.py` 的 `lifespan` 启动阶段：

1. **立即检测**：`await refresh_wechat_health_status()` 获取初始状态
2. **启动时自动恢复**：若不在线，`await _try_auto_restart()` 同步等待恢复完成
3. **启动轮询**：`start_wechat_health_checker(interval_seconds=3)` 后台每 3 秒检测

### 2.2 检查流程

每次 `_check_once()` 通过**单一接口**完成所有判断：

| 步骤 | 动作 | 判定方式 |
|------|------|----------|
| 1. 前置校验 | 检查 `selected_wxid` 是否配置 | 为空则直接 `online=False` |
| 2. 调用 overview | `POST {base_url}/api/wechat/overview` | 连接失败 → "API 服务不可达" |
| 3. 匹配实例 | 按 `wxid` 匹配，多开场景优先选 `login_status=true` 的 | 无匹配 → "不在运行列表中" |
| 4. 判断登录 | **仅以 `login_status` 为准** | `false` → "实例未登录" |

> ⚠️ `nickname`、`attached`、`pid` 等字段不参与在线判断，因为它们可能是历史缓存。

### 2.3 自动恢复机制

当状态从**在线变为离线**时，触发自动恢复（`_try_auto_restart`）：

```
检测到离线
  │
  ├─ 写系统动态（紧急）
  ├─ 写系统消息（error 级别）
  │
  └─ 发起 _try_auto_restart()（后台 asyncio Task）
       │
       ├─ 第1次: POST /api/wechat/start (force_new=false)
       │         等待 10 秒
       │         POST /api/wechat/overview 查找已登录实例
       │         ↓ 成功 → 自动选上实例 + 重连WS + 通知前端
       │         ↓ 失败 ↓
       │
       └─ 第2次: POST /api/wechat/start (force_new=false)
                 等待 10 秒
                 POST /api/wechat/overview 查找已登录实例
                 ↓ 成功 → 同上
                 ↓ 失败 → 标记离线 + 语音告警(×3) + 系统消息 + 前端弹窗
```

恢复期间 `_recovering=True`，前端 Dashboard 显示"恢复中"（黄色脉冲点），不显示离线。

### 2.4 自动选择实例

恢复成功后，从 overview 中找到已登录实例：
- **优先**匹配原 `selected_wxid`
- 找不到则选任意 `login_status=true` 的实例
- 如果 wxid 变化，自动 `UPDATE wechat_config SET selected_wxid = :new_wxid`

### 2.5 告警通知（全渠道）

状态变化时的通知方式：

| 事件 | 系统动态 | 系统消息 | 前端弹窗 | 语音告警 |
|------|---------|---------|---------|---------|
| 离线检测到 | ✅ urgent | ✅ error | — (等恢复结果) | — |
| 自动恢复成功 | — | ✅ info | ✅ success 弹窗 | — |
| 自动恢复失败 | — | ✅ error | ✅ warning 弹窗 | ✅ ×3 次 |
| 轮询恢复在线 | — | ✅ info | ✅ success 弹窗 | — |

### 2.6 状态暴露

- 后端：`get_wechat_health_status()` 返回 `{online, recovering, last_checked_at, last_error, polling}`
- 前端 Dashboard：三态显示
  - 🟢 已连接（`online=true`）
  - 🟡 恢复中（`recovering=true`，黄色脉冲动画）
  - 🔴 未连接（两者均 `false`）
- 前端 MainLayout：通过 `/ws/notify` 实时监听 `wechat_online`/`wechat_offline` 事件
  - 用户登录时自动检查初始状态，离线则弹窗提醒

## 三、ERP 健康检查 (`erp_health.py`)

### 3.1 检查方式

每 20 秒轮询一次，通过 ERP 登录 + 获取账套信息验证连接。

### 3.2 告警通知

| 事件 | 系统动态 | 系统消息 | 语音告警 |
|------|---------|---------|---------|
| 离线 | ✅ urgent | ✅ error | ✅ ×3 次 |
| 恢复 | — | ✅ info | — |

## 四、WebSocket 长连接 (`wechat_ws_service.py`)

### 4.1 连接管理

`WechatWsService` 单例，维护 `connections: Dict[instance_id, state]`。

#### 状态机
```
connecting → open → (收消息中) → 断开 → closed → (sleep 5s) → connecting → ...
                                    ↑
                               异常/网络中断
```

#### 连接建立时机
| 场景 | 调用 |
|------|------|
| 系统启动 | `main.py` → `auto_connect_from_saved_config()` |
| 保存企微配置 | `wechat_config.py` → `auto_connect_from_saved_config()` |
| 手动连接 | 前端 → `POST /api/wechat/ws/connect` |
| 自动恢复成功 | `_try_auto_restart()` → `auto_connect_from_saved_config()` |

### 4.2 自动重连

WS 断开后等 5 秒无条件重试，`manual=True` 时不重连。

## 五、消息接收双通道

| 通道 | 路径 | 特点 |
|------|------|------|
| **HTTP 回调** | `POST /api/wechat/callback/http` 或 `/api/wechat/qwmspush` | 被动接收，不需维护连接 |
| **WebSocket** | `wechat_ws_service` 主动连接 | 实时推送，需要维护长连接 |

两个通道都走 `ingest_runtime_message()`，消息通过 `message_server_id` 去重。

## 六、已实现的能力

- ✅ 每 3 秒健康轮询，仅以 `login_status` 判断在线
- ✅ 掉线后自动调 `/api/wechat/start` 智能启动，最多重试 2 次
- ✅ 恢复后自动选上新实例 + 重连 WS
- ✅ 恢复期间前端显示"恢复中"状态（黄色脉冲点）
- ✅ 前端右下角实时弹窗通知（通过 ws_notify）
- ✅ 服务器语音告警（Windows SAPI，重复 3 次）
- ✅ 系统消息 + 系统动态双写
- ✅ 启动时立即检测 + 自动启动企微

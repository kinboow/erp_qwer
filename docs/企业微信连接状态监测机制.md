# 企业微信连接状态监测机制（现状）

## 一、整体架构

系统通过两个独立机制监测企业微信的连接状态：

```
┌─────────────────────────────────────────────────────┐
│                    后端 (FastAPI)                      │
│                                                       │
│  ┌─────────────────┐     ┌──────────────────────┐    │
│  │ wechat_health.py │     │ wechat_ws_service.py │    │
│  │  (HTTP 健康轮询)  │     │  (WebSocket 长连接)   │    │
│  │  每 15 秒一次      │     │  实时收消息            │    │
│  └────────┬────────┘     └──────────┬───────────┘    │
│           │                         │                 │
│     检测 API 可达性              维护 WS 连接          │
│     检测实例登录状态             readyState 状态机     │
│           │                         │                 │
│     离线 → 写系统动态            断开 → 5秒重连        │
│                                                       │
└───────────────────────────┬───────────────────────────┘
                            │
                     NGCBot V3-QW API
                   (第三方企微 Hook 服务)
```

## 二、健康检查轮询 (`wechat_health.py`)

### 2.1 启动方式

`main.py` 的 `lifespan` 启动阶段调用：

```python
start_wechat_health_checker(interval_seconds=15)
```

创建一个后台 asyncio Task，每 15 秒执行一次 `_check_once()`。

### 2.2 检查流程

每次 `_check_once()` 执行两步：

| 步骤 | 动作 | 判定方式 |
|------|------|----------|
| 1. API 可达性 | `GET {base_url}/api/health` | HTTP 状态码 200 |
| 2. 实例登录状态 | `POST {base_url}/api/wechat/overview` | 找到 wxid 匹配的实例，且 `status`/`attached`/`pid` 任一为真，且 `login_status` 为真或有 `nickname` |

- **两步都通过** → `online = True`
- **任一失败** → `online = False`，记录 `last_error` 原因

### 2.3 离线告警

在 `refresh_wechat_health_status()` 中：

```python
if _prev_online and not current_online:
    # 从在线变为离线
    create_activity_background(
        title="企微连接服务离线",
        content=f"企微连接检测失败：{error_msg}",
        type="urgent",
        source="wechat_health",
    )
```

仅在**状态变化时**（在线 → 离线）写一条紧急系统动态，连续离线不重复告警。

### 2.4 状态暴露

- 后端：`get_wechat_health_status()` 返回 `{online, last_checked_at, last_error, polling}`
- 前端 Dashboard：显示红/绿状态点，点击可手动触发 `POST /api/dashboard/refresh-wechat-health`

### 2.5 局限性

| 问题 | 说明 |
|------|------|
| **只检测不恢复** | 发现离线后不会自动重连 WS，也不会自动重启实例 |
| **无通知渠道** | 仅写系统动态到数据库，无微信/邮件/声音通知 |
| **15 秒间隔** | 最长可能 15 秒才发现掉线 |
| **不区分原因** | API 不可达 vs 实例未登录 vs 实例崩溃 统一记为离线 |

## 三、WebSocket 长连接 (`wechat_ws_service.py`)

### 3.1 连接管理

`WechatWsService` 是一个单例，维护 `connections: Dict[instance_id, state]`。

#### 状态机
```
connecting → open → (收消息中) → 断开 → closed → (sleep 5s) → connecting → ...
                                    ↑
                               异常/网络中断
```

#### 连接建立时机
| 场景 | 调用 |
|------|------|
| 系统启动 | `main.py` → `auto_connect_from_saved_config()` |
| 保存企微配置 | `wechat_config.py` → `auto_connect_from_saved_config()` |
| 手动连接 | 前端 → `POST /api/wechat/ws/connect` |

### 3.2 自动重连机制

在 `_run_connection()` 中：

```python
async def _run_connection(self, instance_id, url):
    while True:
        if state.get("manual"):  # 手动断开则不重连
            return
        try:
            state["readyState"] = "connecting"
            async with websockets.connect(url) as websocket:
                state["readyState"] = "open"
                async for message in websocket:
                    # 处理消息...
        except asyncio.CancelledError:
            raise
        except Exception as exc:
            state["readyState"] = "closed"
            state["lastError"] = str(exc)
            await asyncio.sleep(5)  # 5秒后重连
```

- **自动重连**：WS 断开后等 5 秒无条件重试，死循环永不退出
- **手动断开**：调用 `disconnect()` 设置 `manual=True`，循环检测后退出
- **无退避策略**：始终 5 秒重连，不会指数退避

### 3.3 局限性

| 问题 | 说明 |
|------|------|
| **固定 5 秒重连** | 无指数退避，API 服务长时间不可用时会持续高频重连 |
| **WS 重连 ≠ 消息恢复** | WS 断开期间的消息会丢失，重连后不会回补 |
| **不通知前端** | readyState 变化不会推送给前端，前端需轮询 `/ws/status` |
| **与健康检查独立** | 健康检查发现离线不会触发 WS 重连，两个模块互不感知 |

## 四、消息接收双通道

系统有两个消息入口，互为备份但不自动切换：

| 通道 | 路径 | 特点 |
|------|------|------|
| **HTTP 回调** | `POST /api/wechat/callback/http` 或 `/api/wechat/qwmspush` | 被动接收，不需维护连接；依赖 NGCBot 配置了回调地址 |
| **WebSocket** | `wechat_ws_service` 主动连接 | 实时推送，需要维护长连接 |

两个通道都走 `ingest_runtime_message()`，消息通过 `message_server_id` 去重。

---

## 五、掉线后的影响

当企微连接断开时：

1. **WebSocket 通道**：断开后 5 秒重连，期间消息丢失
2. **HTTP 回调通道**：如果 NGCBot 侧配置了 HTTP 回调，则不受 WS 断开影响
3. **健康检查**：15 秒内检测到离线，写一条系统动态，**但不做任何恢复操作**
4. **AI 对话**：消息丢失意味着 AI 看不到部分客户消息，可能导致漏单
5. **发货扫码**：发货图片丢失不会自动重扫

### 当前没有的能力

- ❌ 掉线后自动重启 NGCBot 实例
- ❌ 掉线后微信/邮件通知管理员
- ❌ 重连后回补断开期间的消息
- ❌ 前端实时显示 WS 连接状态变化（需手动刷新）
- ❌ 智能退避重连策略
- ❌ 健康检查与 WS 服务联动（检测到离线后主动重连 WS）

# 客户群消息处理流程

> **入口函数**: `wechat_runtime_compat.py::ingest_runtime_message`
>
> 所有来自企微 HTTP 回调的消息统一经过此函数处理。本文档仅覆盖**客户群**的消息处理逻辑，发货群扫码流程另见相关文档。

---

## 一、消息接收与预处理

```
企微回调 POST /api/wechat/callback/http
         ↓
ingest_runtime_message(db, payload, source, instance_id, wxid)
```

### 1.1 Payload 标准化

- `normalize_runtime_payload(payload)` 统一不同回调格式
- 解析 `wxid`（机器人自身微信 ID）和 `instance_id`（企微实例 DB 主键）
- 若传入 `instance_id` 实际为 wxid（长度 > 10 纯数字），自动查 `wechat_instances` 表转换

### 1.2 写入消息日志

- `record_message_log(db, payload)` → `message_logs` 表
- 存储字段：`msg_uid`、`room_id`、`sender_id`、`sender_name`、`message_type`、`content_preview`、`message_server_id`、`payload_json`
- 返回 `log_result`，后续步骤依赖其 `id`、`room_id`、`message_type`、`sender_id`、`created_at`

### 1.3 撤回消息检测（最高优先级）

```
message.type == 11123 (REVOKE_MESSAGE)
  → 提取被撤回消息的 message_server_id
  → mark_recalled(db, server_id, room_id) → 标记 is_recalled=1, ai_recognized=1
  → 取消对应的 _pending_delayed_tasks（如有）
  → 直接 return
```

### 1.4 媒体自动归档

- 图片/文件消息 → `asyncio.create_task(download_and_archive_background(...))`
- 异步下载到 MinIO OSS，**不阻塞**主流程

### 1.5 发送者身份检测

- 查 `wechat_employee_accounts` 表：发送者 wxid 是否为本公司员工
- **员工消息不进入客户群接单流程**，仅保留日志

### 1.6 群类型分流

| 匹配函数 | 命中 | 处理 |
|----------|------|------|
| `resolve_shipping_room(db, room_id)` | 发货群 | `handle_shipping_scan` → return |
| `resolve_customer_by_room(db, room_id, instance_id)` | 客户群 | **进入第二节** |
| 都不匹配 | 其他群 | 不处理、不回复 → return |

## 二、客户群消息处理（AI 对话 + Function Calling）

> **前置条件**: `customer` 不为空 **且** `sender_is_employee == False`
>
> **核心模块**: `ai_chat_service.py`
>
> **架构**: 每个被监听的客户群（`room_id`）维护独立的 AI 对话上下文，AI 通过工具（Function Calling）自主完成报货全流程。

### 2.1 标记 @bot 消息

- `is_at_bot(payload, bot_wxid, instance_id)` → 命中则 `UPDATE message_logs SET is_at_bot = 1`
- 保留此标记用于日志分析，不再作为流程分支条件

### 2.2 消息内容提取

- `_extract_callback_message(payload, instance_id)` → 提取消息字段（兼容 3 种回调格式）
- 提取 `content_text`、`sender_name`、`attachment_base64`、`attachment_name`

### 2.3 启动宽限期检查

- `_is_after_startup()` → 启动后前 `STARTUP_GRACE_SECONDS`（30s）内**跳过 AI 处理**，避免积压消息被批量送入 AI

### 2.4 送入 AI 对话

> **函数**: `process_customer_group_message()` in `ai_chat_service.py`

**消息预处理**（根据类型构建 user message content）：

| 消息类型 | 处理方式 |
|----------|----------|
| 文字 | `[发送者姓名] 消息内容` |
| 图片 | multimodal content：文字描述 + base64 image_url |
| Excel 文件 | `_excel_to_markdown(base64)` → Markdown 表格（最多 50 行 × 20 列 × 3 Sheet） |
| 其他文件 | `[发送者姓名] （发送了文件 xxx，无法解析）` |

**消息过滤规则**：
- ✅ 非机器人发送的消息
- ✅ 非员工发送的消息（`wechat_employee_accounts` 表中的 wxid）
- ❌ 机器人自身消息（`bot_wxid`）
- ❌ 员工消息（`sender_is_employee`）

### 2.5 AI 对话处理流程

```
1. 保存 user message → ai_chat_messages 表
2. 加载对话历史（最近 MAX_HISTORY_MESSAGES=80 条）
3. 组装 API messages: [system_prompt] + [history]
4. 调用 AI Chat Completions API (含 tools 定义)
5. 处理 AI 响应：
   ├─ 纯文本回复（无工具调用）→ 保存 → 结束
   └─ 包含 tool_calls → 逐个执行工具 → 保存结果 → 回到步骤 4
      └─ 最多 MAX_TOOL_ROUNDS=8 轮（防无限循环）
6. 定期清理超出 MAX_HISTORY_MESSAGES 的旧消息
```

> **对话历史中图片优化**: 5 条以前的图片消息自动去掉 base64，用文字描述 `[图片已省略]` 替代，节省 token。

### 2.6 AI 可用工具

| 工具名 | 描述 | 参数 | 实现 |
|--------|------|------|------|
| `create_order_review` | 创建待审核订单 | `items[]`（product_no, color, size, quantity, remark）, `order_intent` | 直接写入 `downstream_order_reviews`，`source_type='ai_conversation'`，`parse_status='success'` |
| `query_product_catalog` | 查询产品目录 | `keyword`（可选） | 从 `erp_products`（is_current_year=1）+ `product_name_mappings` 查询 |
| `query_product_details` | 查询货号详情 | `product_no` | 返回可选颜色、尺码、别名 |
| `send_group_message` | 向群发消息 | `message`, `at_sender`（可选） | 调用 `send_room_at()` 发送企微消息 |

#### 2.6.1 `create_order_review` — 创建待审核订单

AI 确认报货信息完整（货号、颜色、尺码、数量齐全）后调用：

1. 生成 `review_uid`（格式: `RV` + 日期 + 随机 hex）
2. 写入 `downstream_order_reviews` 表：
   - `source_type = 'ai_conversation'`
   - `parse_status = 'success'`（AI 对话中已完成解析，无需 3 步 AI 解析）
   - `parsed_order_json` = AI 传入的结构化 items
   - `order_intent` = AI 判断的意图（new/replace/append）
3. SSE 通知前端 `notify_review_change("new_review")`

#### 2.6.2 `query_product_catalog` / `query_product_details` — 商品查询

- 复用 `query_current_year_catalog(db)` 加载本年产品 + 别名映射
- `query_product_catalog`: 支持关键词搜索（货号/名称/别名），最多返回 50 条
- `query_product_details`: 精确/别名匹配，返回 `available_colors`、`available_sizes`

#### 2.6.3 `send_group_message` — 向群发消息

- AI 用于：确认收到、询问缺失字段、回复客户
- 支持 `at_sender=true` 以 @触发消息的发送者
- 调用 `send_room_at(db, room_id, message, at_list, instance_id)`

### 2.7 AI 自主报货流程

AI 根据对话上下文自主决策，典型流程：

```
客户: "82761 黑色 M 10件"
  AI → query_product_details("82761")  // 确认颜色尺码有效
  AI → create_order_review([{product_no:"82761", color:"黑色", size:"M", quantity:10}])
  AI → send_group_message("收到，已为您创建报货订单 ✓")

客户: "弯刀裤 要10件"
  AI → query_product_catalog("弯刀裤")  // 查询是否有匹配
  AI → send_group_message("弯刀裤对应货号 82761，请问需要什么颜色和尺码？", at_sender=true)
  
客户: "黑色 M"
  AI → create_order_review([{product_no:"82761", color:"黑色", size:"M", quantity:10}])
  AI → send_group_message("收到 ✓")
```

### 2.8 订单意图判断

AI 在对话上下文中自主判断订单意图，无需独立的分类智能体：

| intent | 含义 | AI 判断依据 |
|--------|------|-----------|
| `new` | 新下单 | 无替换/修改相关上下文（默认值） |
| `replace` | 替换旧单 | 客户说"之前那个不要了""换成这个""重新报" |
| `append` | 追加/补充 | 客户说"再加一点""补几件""追加" |

## 三、AI 解析流程（`parse_review_content` — 仅前端手动触发 / 旧架构兼容）

> **入口**: `downstream_orders.py::parse_review_content(db, review_id)`
>
> **注意**: 在新架构下，客户群消息由 AI 对话直接创建结构化订单（`source_type='ai_conversation'`，`parse_status='success'`），**不再经过此 3 步解析**。此流程仅用于：前端手动触发重新解析、旧回调接口兼容。

### 3.0 附件准备

- 图片/文件 且缺少 `attachment_base64` → `_download_review_attachment_content` 从企微 CDN 下载
  - 支持 `wx_download`（CDN url + auth_key + aes_key）和 `c2c_download`（file_id + aes_key）
  - 下载后写入 `attachment_base64` 字段
- **Excel** 额外调用 `_extract_excel_summary(base64)` → 转为 **Markdown 表格**（第一行作表头，最多 50 行 × 20 列 × 3 Sheet）

### 3.1 智能体 A：款号匹配 Agent

> **函数**: `ai_order_parser.extract_product_nos(context_messages, catalog=catalog)`
>
> **Prompt**: `_PRODUCT_NO_EXTRACT_PROMPT_TEMPLATE`（动态注入本年产品目录）

**前置**: `query_current_year_catalog(db)` — 加载 `erp_products` 表中 `is_current_year=1` 的全部产品 + `product_name_mappings` 别名 + `color`/`spec` 字段

**职责**:
- 从客户消息中识别产品，与备选目录匹配
- 判断图片旋转角度

**返回**: `{"product_nos": [...], "no_match": false, "rotation_angle": 0}`

**代码层硬校验**: 只保留在 catalog `valid_pnos` 集合中的款号。无有效款号 → `parse_status='failed'` → **中止**。

### 3.1.5 图片旋转

- `rotation_angle != 0` → `rotate_images_in_messages(context_messages, angle)` 用 PIL 旋转

### 3.2 从商品目录获取上下文（非 AI）

> **函数**: `build_context_from_catalog(catalog, product_nos)`

直接从步骤 1 已加载的 catalog 提取，不再查数据库：
- 每个款号的可选颜色（`color`）、尺码（`spec`）
- 别名映射（`product_name_mappings`）

```json
{
  "products": {"82761": {"colors": ["黑色", "奶油白"], "sizes": ["S", "M", "L", "XL"]}},
  "mappings": {"弯刀裤": "82761"}
}
```

### 3.3 智能体 B：订单解析 Agent

| 条件 | 调用方法 | System Prompt |
|------|----------|--------------|
| 有上下文（`products` 非空） | `parse_with_product_context()` | 动态注入每款号可选颜色/尺码/映射 |
| 无上下文 | `parse_batch(catalog=catalog)` | `ORDER_PARSER_SYSTEM_PROMPT` + 目录约束后缀 |

**输出格式**:
```json
{
  "items": [{"product_no": "82761", "color": "黑色", "sizes": [{"size": "M", "qty": 10}], "remark": ""}],
  "remark": "",
  "uncertainties": []
}
```

### 3.4 代码层硬校验

1. `_normalize_order(parsed)` — 标准化格式
2. 用 catalog 的 `valid_pnos` 过滤非本年产品款号
3. 过滤后为空 → `parse_status='failed'` → **中止**

### 3.5 解析成功

```sql
UPDATE downstream_order_reviews
SET parse_status = 'success', parsed_order_json = :json
```
→ SSE 通知前端

## 四、前端人工审核

> 详见 `通用审核流程.md`

审核记录出现在前端列表中，审核员可以：

- **审核通过** → ERP 创建订单 + 自动审核 + 自动打印
- **替换旧单** → 取消未发货 + 创建新单
- **手动录单** → 用手动数据创建订单
- **废单** → 标记作废
- **恢复待审** → 从废单/异常恢复

## 五、完整流程图

```
企微回调 POST /api/wechat/callback/http
  │
  ▼
ingest_runtime_message
  │
  ├─ 1.2 record_message_log → message_logs
  │
  ├─ 1.3 type=11123? ──YES──▶ mark_recalled → return
  │
  ├─ 1.4 图片/文件? → 异步归档 OSS
  │
  ├─ 1.5 发送者是员工? → 跳过客户群处理
  │
  ├─ 1.6 发货群? ──YES──▶ handle_shipping_scan → return
  │
  ├─ 1.6 客户群 + 非员工?
  │   │
  │   ├─ 2.1 标记 @bot（日志分析用）
  │   ├─ 2.2 _extract_callback_message → 提取内容/附件
  │   ├─ 2.3 启动宽限期内? → 跳过 AI
  │   │
  │   └─ 2.4 process_customer_group_message (ai_chat_service.py)
  │       │
  │       ├─ 构建 user message:
  │       │   ├─ 文字 → "[发送者] 内容"
  │       │   ├─ 图片 → multimodal (text + base64)
  │       │   └─ Excel → Markdown 表格
  │       │
  │       ├─ 保存到 ai_chat_messages
  │       ├─ 加载对话历史 (最近 80 条)
  │       ├─ 调用 AI Chat API + tools
  │       │
  │       └─ AI 响应处理（最多 8 轮 tool call）:
  │           ├─ query_product_catalog → 查询产品目录
  │           ├─ query_product_details → 查询颜色/尺码
  │           ├─ send_group_message → @客户询问/确认
  │           └─ create_order_review → 创建待审核订单
  │               ├─ source_type='ai_conversation'
  │               ├─ parse_status='success'
  │               └─ SSE → 前端待审核列表
  │
  └─ 其他群 → return
```

## 六、AI 架构说明

### 客户群 — AI 对话 + Function Calling（新架构）

| 组件 | 说明 |
|------|------|
| System Prompt | `CUSTOMER_GROUP_SYSTEM_PROMPT` in `ai_chat_service.py` |
| 对话存储 | `ai_chat_messages` 表，per-room 独立上下文 |
| 工具定义 | `TOOL_DEFINITIONS` — 4 个工具（见 2.6） |
| 模型选择 | 有图片 → `vision_model`；纯文字 → `model` |
| API 格式 | OpenAI 兼容（字节跳动豆包 / 通义千问 / 自定义） |

### 前端手动解析 — 3 步 AI 解析（旧架构保留）

| 编号 | 名称 | Prompt 常量 | 调用方法 | 职责 |
|------|------|-------------|----------|------|
| ⑤ | 款号匹配 | `_PRODUCT_NO_EXTRACT_PROMPT_TEMPLATE` | `extract_product_nos()` | 从产品目录匹配款号 + 旋转角度 |
| ⑥ | 订单解析 | `ORDER_PARSER_SYSTEM_PROMPT` / 动态模板 | `parse_with_product_context()` / `parse_batch()` | 结构化解析（货号/颜色/尺码/数量） |

所有 AI 配置统一读取 `ai_config` 表（DB 优先）或 `.env` 回退。

## 七、关键配置项

| 配置项 | 位置 | 默认值 | 说明 |
|--------|------|--------|------|
| `STARTUP_GRACE_SECONDS` | `wechat_runtime_compat.py` | `30` 秒 | 启动宽限期，期间不触发 AI 对话 |
| `MAX_HISTORY_MESSAGES` | `ai_chat_service.py` | `80` 条 | 每个群保留的最大对话消息数 |
| `MAX_TOOL_ROUNDS` | `ai_chat_service.py` | `8` 轮 | 单次消息最大连续工具调用轮数 |
| `CHAT_API_TIMEOUT` | `ai_chat_service.py` | `240` 秒 | AI API 请求超时 |
| AI model | `ai_config` 表 / `.env` | — | 文本模型（需支持 Function Calling） |
| AI vision_model | `ai_config` 表 / `.env` | — | 视觉模型（图片消息时使用） |
| AI temperature | `ai_config` 表 | `0.1` | 低温 = 更确定性输出 |
| AI max_tokens | 代码硬编码 | `16384` | 最大输出 token |

## 八、关键数据表

### `ai_chat_messages` — AI 对话消息（新增）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK | 主键 |
| `room_id` | VARCHAR(100) | 群聊 ID |
| `role` | VARCHAR(20) | `system` / `user` / `assistant` / `tool` |
| `content` | MEDIUMTEXT | 文本内容 / JSON multimodal |
| `name` | VARCHAR(200) | user=发送人姓名, tool=工具名 |
| `tool_calls` | JSON | assistant 发起的工具调用 |
| `tool_call_id` | VARCHAR(100) | tool 消息对应的 call id |
| `created_at` | DATETIME | 创建时间 |

### `downstream_order_reviews` — 审核记录（关键字段）

| 字段 | 说明 |
|------|------|
| `review_uid` | 审核记录唯一标识 |
| `source_type` | `ai_conversation`（新架构）/ `wechat_*`（旧架构） |
| `parse_status` | `pending` / `pending_attachment` / `success` / `failed` |
| `review_status` | `pending` / `approved` / `rejected` / `voided` |
| `parsed_order_json` | 结构化订单 JSON（AI 对话直接填写 / 旧架构 3 步解析） |
| `order_intent` | 意图分类：`new` / `replace` / `append` |

### `message_logs` — 消息日志（关键字段）

| 字段 | 说明 |
|------|------|
| `msg_uid` | 消息唯一 ID |
| `room_id` / `sender_id` | 群 ID / 发送人 ID |
| `message_type` | 消息类型 |
| `content_preview` | 内容预览 |
| `is_at_bot` | 是否 @机器人 |
| `is_recalled` | 是否已撤回 |
| `message_server_id` | 企微服务端消息 ID（用于撤回匹配） |

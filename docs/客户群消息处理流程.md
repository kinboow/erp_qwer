# 客户群消息处理流程

> 入口函数: `wechat_runtime_compat.py::ingest_runtime_message`
> 
> 所有来自企微回调的消息统一经过此函数，根据消息类型和群类型分流处理。
> 客户群消息统一走通用审核链 `create_review_from_callback`，由人工在前端审核后再下单到 ERP。

---

## 一、消息接收与预处理

```
企微回调 POST /api/wechat/callback/http
         ↓
ingest_runtime_message(db, payload, source, instance_id, wxid)
```

### 1.1 Payload 标准化
- 调用 `normalize_runtime_payload(payload)` 统一不同格式的消息体
- 解析 `wxid`（机器人自身）和 `instance_id`（企微实例 DB ID）

### 1.2 写入消息日志
- 调用 `record_message_log(db, payload)` 写入 `message_logs` 表
- 提取并存储 **`message_server_id`**（从 `data.message_server_id` / `data.server_id` / `data.svr_id` 中取）
- 返回 `log_result` 包含 `id`, `room_id`, `message_type`, `sender_id`, `message_server_id` 等

### 1.3 撤回消息检测（优先级最高）

```
如果 message.type == 11123（REVOKE_MESSAGE）:
  1. 从 payload 提取被撤回消息的 message_server_id
  2. 在 message_logs 表中根据 message_server_id + room_id 查找原始消息
  3. 标记 is_recalled = 1, ai_recognized = 1（防止补扫）
  4. 直接 return，不再继续后续流程
```

### 1.4 媒体自动归档
- 图片/文件消息：异步调用 `download_and_archive_background` 下载到 MinIO OSS
- **此步骤不阻塞主流程，异步执行**

### 1.5 发送者身份检测
- 查询 `wechat_employee_accounts` 表判断发送者是否为本公司员工
- **员工发送的消息不进入客户群接单流程**（跳过 AI 识别）

### 1.6 群类型分流
- 查询 `room_id` 确定群类型：
  - `resolve_shipping_room(db, room_id)` → 发货群 → **走发货扫码流程（不在本文档范围）**
  - `resolve_customer_by_room(db, room_id)` → 客户群 → **进入下方客户群审核流程**
  - 都不是 → 不处理、不回复，仅记录 debug 日志后直接返回

## 二、客户群消息处理

> 前置条件: `customer` 不为空 且 `sender_is_employee == False`

### 2.1 标记 @bot 消息

- 检测 `is_at_bot(payload, bot_wxid, instance_id)`
- 如果是 → `UPDATE message_logs SET is_at_bot = 1`

### 2.2 报货验证（回复前置判断）

> 函数: `AIOrderParser.validate_order(context_messages, db)`

在回复"收到"之前，先用 AI 判断消息是否为报货信息：

1. 调用 `_extract_callback_message(payload)` 提取消息字段
2. 调用 `_build_validate_context(extracted, log_result)` 构建验证上下文
3. 调用 `validate_order` AI 判断 `is_order`

**分支逻辑**:
- `is_order == False` → **不回复、不处理，直接跳过**
- `is_order == True` → 继续下方步骤 2.3
- AI 验证失败 → 保守当作报货处理
- 图片/Excel 无 base64 无法验证 → 保守当作报货处理

### 2.3 回复"收到"（仅报货消息）

只有通过报货验证的消息才回复，且仅限以下类型：

| 消息类型 | 触发条件 | 回复"收到" |
|----------|----------|------------|
| **@机器人文字** | `is_at_bot() == True` | ✅（仅启动宽限期后） |
| **图片** | `message_type in ("image", "img", "picture")` | ✅（仅启动宽限期后） |
| **Excel 文件** | `message_type == "file"` 且文件名 `.xlsx`/`.xls` | ✅（仅启动宽限期后） |
| **普通文字** | `message_type == "text"` 且非 @bot | ✖ 不回复 |

```
asyncio.create_task(_reply_received(room_id, sender_id, instance_id))
  → send_room_at(room_id, "收到，正在处理中…", at_list=[sender_id])
  → at_list 中是消息发送人（客户）的 wxid，不是机器人实例
  → 启动后前 30 秒内收到的积压消息不会回复"收到"
```

### 2.4 创建审核记录 + AI 自动解析

> 函数: `create_review_from_callback(db, normalized_payload, instance_id)`

**只有通过报货验证的消息**才进入此流程：

1. **提取消息字段** — `_extract_callback_message(payload)` 兼容 3 种回调格式
2. **跳过检查** — 非群消息 / 不支持的类型 / 空内容 → skip
3. **写入 `downstream_order_reviews` 表** — 含 `review_uid`、消息内容、附件信息
4. **自动调用 `parse_review_content`** — 3 步 AI 解析（见下方第三节）
5. **SSE 通知前端** — `notify_review_change("new_review")`

---

## 三、AI 解析流程（`parse_review_content`）

> 入口: `downstream_orders.py::parse_review_content(db, review_id)`

### 3.0 附件准备

- 如果是 `image`/`file` 且缺少 `attachment_base64`：
  - 调用 `_download_review_attachment_content` 从企微 CDN 下载
  - 支持 `wx_download`（CDN url+auth_key+aes_key）和 `c2c_download`（file_id+aes_key）两种模式
  - 下载后存入 `attachment_base64` 字段
- Excel 文件额外调用 `_extract_excel_summary` 提取文本摘要

### 3.1 — 智能体 A：款号匹配 Agent

> 函数: `ai_order_parser.extract_product_nos(context_messages, catalog=catalog)`

**前置**: `query_current_year_catalog(db)` 加载本年产品目录（`erp_products` 表中 `is_current_year=1`）

**核心逻辑**: 将本年产品目录（款号 + 名称 + 别名）作为备选项注入 System Prompt，AI 直接从备选目录中匹配客户提到的产品。

<details>
<summary>🔧 System Prompt（_PRODUCT_NO_EXTRACT_PROMPT_TEMPLATE）</summary>

```
你是一个服装行业订单内容提取助手。

以下是本年产品目录（备选项），你只能从这个目录中选择款号：
{catalog_text}

任务1：从客户发来的内容中，识别出客户想要订购的产品，然后从备选目录中匹配对应的款号。
- 匹配成功的款号放入 product_nos 数组
- 找不到任何匹配则 no_match = true

任务2：判断图片旋转角度（rotation_angle）
```
</details>

**AI 返回**: `{"product_nos": [...], "no_match": false, "rotation_angle": 0}`

**代码层硬校验**:
- 确保 AI 返回的款号确实在 catalog 的 `valid_pnos` 中
- `no_match == true` 或无匹配款号 → `parse_status = 'failed'` → **中止**
- 有匹配 → 继续

### 3.1.5 — 图片旋转

- 如果 `rotation_angle != 0` → `rotate_images_in_messages` 用 PIL 旋转

### 3.2 — 从商品列表获取上下文（非 AI）

> 函数: `build_context_from_catalog(catalog, product_nos)`

- 直接从步骤 1 已加载的 `catalog` 中提取，无需再查数据库
- 每个款号的可选颜色（`color` 字段）、尺码（`spec` 字段）
- 所有别名映射（`product_name_mappings` 表，已随 catalog 一起加载）

**返回格式**:
```json
{
  "products": {
    "82761": {"colors": ["黑色", "奶油白"], "sizes": ["S", "M", "L", "XL"]}
  },
  "mappings": {"弯刀裤": "82761"}
}
```

### 3.3 — 智能体 B：订单解析 Agent

#### 有上下文 → `parse_with_product_context`

System Prompt 动态注入每个款号的可选颜色、尺码、映射关系。

<details>
<summary>🔧 动态 System Prompt 模板（_CONTEXT_PARSER_PROMPT_TEMPLATE）</summary>

```
【⚠️ 固定配置 — 各款号可选颜色和尺码】
款号 82761:
  可选颜色: ["黑色", "奶油白", "花灰色"]
  可选尺码: ["S", "M", "L", "XL"]

款号映射关系：{"弯刀裤": "82761"}

【核心执行规则】
1. 按款号匹配颜色和尺码，智能匹配手写简写/俗称
2. 每个颜色单独成行，sizes 包含全部可选尺码，无标注填0
3. 手写模糊/涂改的数量填0
4. 必须只输出纯JSON

{
  "items": [{"product_no": "", "color": "", "sizes": [{"size": "", "qty": 0}], "remark": ""}],
  "remark": ""
}
```
</details>

#### 无上下文 → `parse_batch`

使用 `ORDER_PARSER_SYSTEM_PROMPT` + `_ORDER_PARSER_CATALOG_SUFFIX`（注入完整本年产品目录约束）

<details>
<summary>🔧 System Prompt（ORDER_PARSER_SYSTEM_PROMPT + 目录约束后缀）</summary>

```
你是一个服装订单解析助手。请把客户通过企微发送的文本、图片、表格内容解析成结构化订单 JSON。
要求：
1. 只提取货号、颜色、尺码、数量、备注
2. items 中每个款号+颜色单独成行
3. 不确定的保留在 uncertainties 中
4. 严格返回 JSON

【重要约束 — 本年产品目录】
product_no 只能从此目录中选择。
```
</details>

### 3.4 — 代码层硬校验

- `_normalize_order(parsed)` 标准化格式
- 用 `catalog` 的 `valid_pnos` 过滤非本年产品款号
- 过滤后为空 → `parse_status = 'failed'` → **中止**

### 3.5 — 解析成功

```sql
UPDATE downstream_order_reviews
SET parse_status = 'success', parsed_order_json = ''
```

## 四、前端人工审核

> 详见 `通用审核流程.md`

AI 解析完成后，审核记录出现在前端审核列表中。审核员可以：

- 审核通过 → ERP 创建订单 + 自动审核 + 自动打印
- 替换旧单 → 取消未发货 + 创建新单
- 手动录单 → 用手动数据创建订单
- 废单 → 标记作废
- 恢复待审 → 从废单/异常恢复

## 五、完整流程图

```
企微回调
  │
  ▼
ingest_runtime_message
  │
  ├─ 记录 message_logs（含 message_server_id）
  │
  ├─ type=11123? ──YES──▶ _handle_recall → 标记撤回 → return
  │
  ├─ 媒体归档（异步后台）
  │
  ├─ 发货群? ──YES──▶ handle_shipping_scan → return
  │
  ├─ 客户群 + 非员工?
  │   │
  │   ├─ 报货验证: validate_order(AI)
  │   │   ├─ is_order=false → 不回复、不处理 → return
  │   │   └─ is_order=true ↓
  │   │
  │   ├─ @bot / 图片 / Excel? → 回复"收到，正在处理中…"（@发送人）
  │   │
  │   └─ create_review_from_callback
  │       │
  │       ├─ 非群消息/不支持类型/空内容 → skip
  │       │
  │       ├─ 写入 downstream_order_reviews 表
  │       │
  │       └─ parse_review_content（3步 AI 解析）
  │           │
  │           ├─ 步骤1: 智能体A 从备选目录匹配款号 + 旋转判断
  │           │         → 代码层校验 AI 返回的款号在目录中
  │           │         → no_match/无匹配 → parse_status=failed → 结束
  │           │
  │           ├─ 步骤2: 从商品列表获取上下文（颜色/尺码/映射）
  │           │
  │           ├─ 步骤3: 智能体B 带上下文订单解析
  │           │         → 代码层硬校验（目录过滤）
  │           │         → 过滤后为空 → parse_status=failed → 结束
  │           │
  │           └─ 解析成功 → parse_status=success
  │                         → SSE 通知前端
  │                         → 前端人工审核 → ERP 下单
  │
  └─ 其他群 → 不处理，直接 return
```

## 六、关键配置项

| 配置项 | 位置 | 默认值 | 说明 |
|--------|------|--------|------|
| `STARTUP_GRACE_SECONDS` | `wechat_runtime_compat.py` | `30` 秒 | 启动后多久内的消息不回复"收到" |
| AI model | `ai_config` 表 或 `.env` | - | 文本模型 |
| AI vision_model | `ai_config` 表 或 `.env` | - | 视觉模型（处理图片时使用） |
| AI temperature | `ai_config` 表 | `0.1` | 温度参数（低温 = 更确定性输出） |
| AI max_tokens | 代码硬编码 | `16384` | 最大输出 token |
| API 超时 | 代码硬编码 | `180s`（千问）/ `240s`（豆包） | HTTP 请求超时 |

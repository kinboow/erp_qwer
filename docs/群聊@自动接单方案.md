# 群聊 @机器人 自动接单方案（方案 B：审核队列模式）

## 一、概述

当已匹配下游客户的微信群中有人 **@机器人** 时，系统自动采集 @前后的上下文消息（文字、图片、Excel），
调用 AI 进行订单解析，解析结果进入 **审核队列**，人工确认后通过 `POST /api/sales-orders` 下单到 ERP。

```
群消息回调 → 检测@机器人 → 采集上下文消息 → AI批量解析 → 写入审核队列 → 人工审核 → 下单ERP → 群内回复结果
```

| 模块 | 文件 | 能力 |

## 五、核心流程设计

### 5.1 @检测

在 `ingest_runtime_message()` 中，消息写入 `message_logs` 后增加一个检测步骤：

```python
# 伪代码
if is_at_bot(payload, bot_wxid):
    room_id = extract_room_id(payload)
    customer = resolve_customer_by_room(db, room_id)
    if customer:
        # 触发上下文采集 + AI解析
        asyncio.create_task(handle_at_order(db_factory, room_id, customer, trigger_message))
```

**@检测方式**（兼容多种回调格式）：
- `message.data.at_list` 包含机器人 wxid
- `content` 中包含 `@机器人昵称`
- `message.data.is_at_me` == true

### 5.2 上下文采集（滑动窗口 + sender 过滤）

**问题：** 群聊中发消息常被别人插话打断，且发图片/文件比发文字慢，可能过了十几秒才发出来。

```
实际场景示例：
A: @机器人 下单                    ← 触发
   B: 好的收到                         ← 别人插话（忽略）
A: 001白色 M10件 L20件              ← 采集
   C: 在不在？                          ← 别人插话（忽略）
A: [图片]                              ← 采集（20秒后才发出）
   (无新消息超过15秒)                  ← 窗口关闭，开始解析
```

**方案：滑动窗口（Sliding Window）**

不用固定等待时间，而是每次收到同一 sender 的新消息就“续命”等待时间：

```python
# 伪代码
async def collect_context(room_id, sender_id, trigger_msg_id):
    IDLE_TIMEOUT = 15   # 无新消息超过15秒 → 关闭窗口
    MAX_WAIT    = 120   # 最多等待2分钟（防止无限等待）
    
    start = now()
    last_msg_time = now()
    collected_ids = set()
    
    # 1. 向上回溯：同一 sender、同一群、最近5分钟、最多20条
    history = query_message_logs(
        room_id=room_id, sender_id=sender_id,
        since=now() - 5min, limit=20
    )
    collected_ids.update(msg.id for msg in history)
    
    # 2. 滑动窗口向下收集
    while True:
        elapsed = now() - start
        idle = now() - last_msg_time
        
        if elapsed > MAX_WAIT:   break   # 超过总时限
        if idle > IDLE_TIMEOUT:  break   # 无新消息超时
        
        new_msgs = query_new_messages(
            room_id=room_id, sender_id=sender_id,
            after=trigger_msg_id, exclude=collected_ids
        )
        if new_msgs:
            collected_ids.update(msg.id for msg in new_msgs)
            last_msg_time = now()       # 收到新消息 → 重置空闲计时
        
        await sleep(2)  # 每2秒检查一次
    
    return all_collected_messages
```

**关键规则：**
1. **只采集同一 sender_id**：别人的插话自动忽略，不影响采集
2. **滑动窗口 15秒**：每收到同一 sender 的新消息，重置 15秒倒计时
3. **总时限 2分钟**：防止无限等待（如对方一直在发消息）
4. **向上回溯 5分钟**：采集 @前同一 sender 最近的消息（可能先发了文字再 @）
5. **消息类型**：收集 `text`、`image`、`file` 三种
6. **去重**：按 `message_logs.id` 去重

### 5.3 AI 批量解析

将采集到的上下文合并为一个请求发给 AI：

```python
# 构造多模态消息
messages = [
    {"role": "system", "content": ORDER_PARSE_SYSTEM_PROMPT},
    {"role": "user", "content": [
        {"type": "text", "text": "客户: XX服装店\n以下是客户在群里发的下单消息："},
        {"type": "text", "text": "消息1: 001白色M10件L20件"},
        {"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}},  # 如有图片
        {"type": "text", "text": "消息3: 002黑色均码50件"},
    ]}
]
```

**解析策略：**
- 纯文本消息：拼接后用 `OPENAI_MODEL` 解析
- 含图片消息：使用 `GLM-4.6V` 多模态能力直接输入图片
- 含 Excel/文件：直接作为文件输入给 `GLM-4.6V`，无需额外预处理
- 混合类型：全部合并为一个多模态请求，GLM-4.6V 原生支持文字+图片+文件混合输入

### 5.4 写入审核队列

AI 解析成功后，将结果写入 `downstream_order_reviews` 表：

| 字段 | 值 |
|------|------|
| `source_type` | `wechat_at_order`（新类型，区分于普通消息触发） |
| `room_id` | 群ID |
| `sender_id` | @机器人的发送者 |
| `content_text` | 拼接的上下文文本摘要 |
| `customer_id` | 匹配到的下游客户ID |
| `parsed_order_json` | AI 解析结果 JSON |
| `parse_status` | `success` / `failed` |
| `review_status` | `pending`（等待人工审核） |

### 5.5 人工审核 → ERP下单

**复用现有审核流程**，无需改动：
1. 前端「下游订单审核」页面显示待审核记录
2. 人工确认/修改订单内容
3. 点击「审核通过」→ `approve_review()` → `ERPBridge.create_sales_order()`
4. 或点击「替换下单」→ 先取消旧未发货单再下新单

### 5.6 群内自动回复

| 时机 | 回复内容 |
|------|---------|
| @检测成功，开始解析 | `📋 已收到下单消息，正在解析中...` |
| AI解析成功 | `✅ 订单已识别：XX货号×N件，已提交审核，请等待确认` |
| AI解析失败 | `⚠️ 无法识别订单内容，请重新发送或联系客服` |
| 人工审核通过并下单成功 | `✅ 订单已确认，ERP单号：XS20250426001` |
| 非匹配客户群 | 不回复（静默忽略） |

**回复方式**：调用企微 API `POST /api/{wxid}/send/room_at`
```json
{
  "conversation_id": "R:{room_id}",
  "content": "回复文本",
  "at_list": ["{sender_id}"]
}
```

## 十、风险与注意事项

1. **防重复触发**：同一条@消息不能重复处理，用 `message_logs.id` + `at_order_contexts` 做幂等
2. **滑动窗口采集**：每次收到同一 sender 新消息重置 15秒倒计时，总时限 2 分钟。别人插话自动过滤。
3. **附件下载延迟**：图片/文件的 base64 可能需要从企微 CDN 下载，要处理超时
4. **并发控制**：同一群同一 sender 短时间内多次@，只处理第一次，后续的合并进同一个采集窗口
5. **非订单@**：客户可能@机器人只是聊天/咨询，AI 需要能识别并返回“非订单内容”
6. **安全**：只处理已匹配客户的群，未匹配群的@静默忽略
